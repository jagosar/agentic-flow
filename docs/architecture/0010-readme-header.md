# Architecture: a generated header at the top of every README that uses the flow (agentic-flow 2.4)
Type: feature · Size: standard

## 1. Goal
Every project that uses agentic-flow gets a centred header at the top of its README: the title, a one-line description and a row of badges (licence, languages, "built with agentic-flow" and, if the project declares them, sponsor buttons). The header is generated without network from what is in the repo, lives between two markers, and is rewritten by `install` on every install and update; nothing outside the markers is ever touched. Template copies get it when the template's README is replaced; the flow's own README carries it too, generated by the same code and kept current by a test. A project can turn it off. It ships in 2.4.0, which is not released yet.

## 2. Scope
### Included
- `agentic.py readme-header [--check]`: writes or checks the header block in `README.md`.
- Badges: licence (from `LICENSE`, `LICENSE.md`, `LICENSE.txt` or `COPYING`), up to four detected languages, "built with agentic-flow" (with the installed version in projects, without it in the flow's own repo), sponsor buttons from `.claude/agentic.json`.
- `install` runs it after copying the flow, guards `README.md` against uncommitted changes, and reports it.
- `reset-readme.yml` (template copies) runs it after writing the stub.
- The flow's README gets its header; docs, upgrade note, tests.
### Excluded (non-goals)
- Dynamic badges that need a service at view time (CI status, coverage, downloads), and counts of agents, skills, hooks or rules (not chosen).
- Rewriting anything below the header. A README that was edited by hand inside the markers keeps its title and description.
- Version bump: still 2.4.0.

## 3. Stack
Python 3.9+ standard library (`unittest`, `re`, `urllib.parse.quote`), GitHub Actions YAML, Markdown.
- Build: `python3 -m compileall -q .claude/bin`
- Tests: `python3 -m unittest discover -s .claude/bin -p "test_*.py"`; docs: `python3 -m unittest discover -s acceptance`, `python3 -m unittest discover -s qa -p "test_qa_docs.py"`.

## 5. Data model
`.claude/agentic.json` (new keys, both optional):
```json
{"readme": {"header": true,
            "sponsors": [{"label": "GitHub Sponsors", "url": "https://github.com/sponsors/someone"},
                         {"label": "Buy Me a Coffee", "url": "https://buymeacoffee.com/someone"}]}}
```
The block written in `README.md` (blank lines inside the `div` are required for GitHub to render the Markdown):
```
<!-- agentic-flow:header:start -->
<div align="center">

# my-project

One sentence that says what it is.

[![licence: MIT](https://img.shields.io/badge/licence-MIT-blue)](LICENSE "the licence file found") ![python](https://img.shields.io/badge/python-informational) [![built with agentic-flow 2.4.0](https://img.shields.io/badge/built%20with-agentic--flow%202.4.0-8A2BE2)](https://github.com/jagosar/agentic-flow) [![GitHub Sponsors](https://img.shields.io/badge/GitHub%20Sponsors-support-ea4aaa)](https://github.com/sponsors/someone)

</div>
<!-- agentic-flow:header:end -->
```

`install` (existing): `"README.md"` joins `guarded`; after the record is written it runs `readme-header` with this version's `agentic.py` and `CLAUDE_PROJECT_DIR=target` (the `rules-sync` pattern) and prints `  README header: <state>`; with `--dry-run` it runs `readme-header --check` instead and prints `  README header: would be added|updated|unchanged|disabled`. Install reads the state from the JSON line on stdout, whatever the exit code (in a dry run, exit 3 just means "would change"), and passes every stderr line of `readme-header` on to its own output, indented. If the call exits 1, it prints `  README header: error: <last stderr line>` and the install still ends `RESULT: OK` (the rules-sync pattern, `agentic.py:1395-1397`).

## 7. Conventions
- English, plain voice; messages name the key or command that fixes them.
- The badge alt texts are lower case words (`licence: MIT`, `python`, `built with agentic-flow 2.4.0`); sponsor alt text is its label.
- Never write `README.md` when the content would not change (no touch, no new line ending change): compare strings first.
- Read and write with `encoding="utf-8", newline=""` (so `\r\n` is seen and kept); the block uses the file's line ending.
- No type annotations in `agentic.py`, which contradicts `.claude/rules/agentic/python.md` ("type annotations on every public signature"): the file has none and must import on Python 3.9; the plan wins (precedence in `common.md`).
- The hub stays at 260 lines: the new script-reference line and the two Configuration lines are paid by three merges: the `run-review` and `run-qa` lines into `python3 .claude/bin/agentic.py run-review | run-qa` with the comment `# code reviewer (read-only), or the QA agent`; the comment line `# Fallback mode: ...` into the `run-pipeline` line as its comment; the comment line `# ...or stage by stage:` into the `run-acceptance` line's comment (`# stage by stage: wave 0, the test-author writes the acceptance tests`). Every `#` stays in its column.
- Commits: one per WP; no model names.

## 8. Work packages and acceptance criteria
### Acceptance criteria
- AC-001 · A README with a title and a description gets the header, once
  - Scenario: a git repo folder `demo` with an MIT `LICENSE`, two `.py` files, `README.md` = `# Demo\n\nA small tool.\n\n## Usage\n\nrun it\n`, no `.claude/agentic.json`, no install record, no `.claude-plugin`.
  - Action: `readme-header` twice.
  - Expected: first run prints `"added"`; the file starts with the start marker; the block contains `# Demo`, `A small tool.`, a badge with `licence-MIT`, one with `python`, one with `built%20with-agentic--flow`; after the end marker comes a blank line and `## Usage`; `# Demo` and `A small tool.` appear once in the file. Second run prints `"unchanged"` and the file's bytes are identical.
  - Must not: duplicate the title or the description; change anything after the block.
  - Check: `test_acceptance_header.py::FirstHeaderTests`
  - WP: WP-01
- AC-002 · An update keeps the edited title and description and changes only the badges
  - Scenario: AC-001's result, with the H1 inside the block edited to `# Demo Tool`, the description to `Edited.`, a line `extra text` added after the block, and `LICENSE` replaced by an Apache 2.0 text.
  - Action: `readme-header`.
  - Expected: `"updated"`; `# Demo Tool` and `Edited.` kept; the licence badge says `Apache--2.0`; `extra text` still there, once.
  - Must not: restore the old title or description; touch lines outside the markers.
  - Check: `test_acceptance_header.py::UpdateTests`
  - WP: WP-01
- AC-003 · READMEs without a leading title, or without a README
  - Scenario: (a) `README.md` = `Some intro\n\n# Later\n`; (b) no `README.md`; (c) `README.md` = `<!-- agentic-flow-template -->\n# agentic-flow\n\nA team.\n`.
  - Action: `readme-header` in each.
  - Expected: (a) block with `# demo` (the folder name), no description, then `Some intro` and `# Later` unchanged; (b) the file is created with the block only; (c) line 1 is still the template marker, line 2 the start marker, the block has `# agentic-flow` and `A team.`, and its "built with" badge has no version.
  - Must not: take a heading that is not the first non-blank line as the title.
  - Check: `test_acceptance_header.py::EdgeTests`
  - WP: WP-01
- AC-004 · Sponsors from the config, with unsafe entries skipped; the header can be turned off
  - Scenario: `.claude/agentic.json` with `readme.sponsors` = a valid GitHub Sponsors entry, one with `http://` url, one with a url containing `)`, one whose label contains `](` followed by a `javascript:` url.
  - Action: `readme-header`; then `readme.header: false` and a README changed by hand; `readme-header` again.
  - Expected: one sponsor badge (the valid one), stderr names the three skipped entries; with `header: false` it prints `"disabled"` and the file is untouched.
  - Must not: write any skipped entry's text into the README.
  - Check: `test_acceptance_header.py::SponsorTests`
  - WP: WP-01
- AC-005 · `install` writes the header, respects uncommitted README changes and reports
  - Scenario: a committed target repo with `README.md` = `# Target\n\nText.\n`.
  - Action: `install --dry-run`; `install`; commit everything; then edit `README.md` without committing and `install` again.
  - Expected: dry run prints `README header: would be added` and does not change `README.md`; install prints `README header: added`, and the badge carries the version in `.claude/agentic-install.json`; the third run exits 3, names `README.md` as uncommitted, and writes nothing.
  - Must not: write `README.md` in a dry run or over uncommitted changes.
  - Check: `test_acceptance_header.py::InstallHeaderTests`
  - WP: WP-01
- AC-006 · `--check`, damaged blocks and a bad config

## 9. Test strategy
- Unit: WP-01 in `test_agentic.py`: `shield_text` escaping, `licence_file` for each known text and an unknown one, language order and the cap, each sponsor rejection rule, `apply_header` cases (block present, marker, no H1, paragraph rules for lists, images and fences, CRLF), idempotence.

Temporary git repos as in `test_acceptance_upgrade.py:38-70`, with one difference that matters: every `readme-header` call is `[sys.executable, <this repo>/.claude/bin/agentic.py, "readme-header", ...]` with `cwd=<tmp repo>` and `env=dict(os.environ, CLAUDE_PROJECT_DIR=str(<tmp repo>))` minus `CLAUDECODE`. Install calls keep the upgrade tests' environment (install takes the target as an argument).
- QA: the whole `.claude/bin` suite and the docs suites; by hand after merging, render the flow's README on GitHub and check that the block is centred and the badges resolve.

## 10. Decisions
- **D1 · Badges (user's choice):** licence and languages, "built with agentic-flow", sponsors when declared. Counts of agents, skills, hooks and rules were not chosen.
- **D2 · Written by install on every install and update (user's choice),** between markers, so updates refresh the badges and nothing else.
- **D3 · Title and description from the README itself (user's choice):** the first H1 and the paragraph after it move into the block the first time, so nothing is duplicated; afterwards the block owns them and edits inside it are kept.
- **D4 · The flow's README uses the same generator (user's choice),** and a test keeps it current.
- **D5 · On by default, off with `readme.header: false`** (my call): the user asked for it in every project; a project that does not want its README touched can say so.
- **D6 · Static shields.io badges, built without network:** a project offline or in CI still gets the same file; dynamic badges are out of scope.
- **D7 · The flow's own badge carries no version:** its README is checked for hard-coded versions (`acceptance/test_docs.py:24`) and its release is the version; projects show the version they installed.
- **D8 · `README.md` is guarded by install:** install already refuses to write over uncommitted changes to the files it touches; the README joins them.
- **D9 · The hub stays at 260 lines** with three merges (section 7), as in 0008 and 0009.
- **D10 · Sponsor entries are validated:** labels and urls end up in a README people render; anything that could break out of the Markdown link or use a non-https scheme is skipped and named.
- **D12 · Install creates `README.md` in a project that has none** (with the block only), and changes a tracked README: the second install before a commit exits 3 because of it, as for any file install touches.
- **D13 · `docs.files` is `docs/assets/`:** the default zone overlaps WP-03 and `validate` refuses `docs/architecture/`; the doc-updater has nothing to write in a by-hand run.
- **D11 · Executed by hand:** WP-01 and WP-03 own paths under `.claude/` (`validate` refuses them); acceptance tests first and red, one commit per WP.

## 11. Risks and open questions
- **First run on a README that starts with badges or an HTML block:** the H1 rule does not match, so the header goes on top with the folder name as title and the old content stays below; the user may want to delete their old title by hand. The install output says the header was added.
- **GitHub rendering:** the `div` needs blank lines around its Markdown; checked by hand after merging, not by a test.
- **A fresh template copy shows the flow's MIT licence and a `python` badge** (the template's own files) until the project changes its licence or code; the next install refreshes the badges.
- **Commit order of the by-hand run:** `test_definitions.py`'s cited-commands check reads every tracked `.md`, including this plan, which cites `agentic.py readme-header`: it fails between the design commit and WP-01's. The design is committed together with WP-01's first commit, or the check is run only after it.
- **`detect_stack` counts JavaScript under `typescript`:** a JS project shows a `typescript` badge. Accepted for now; the badge text is the rules pack name.
